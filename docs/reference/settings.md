## Subscriptions (`subscriptions`)

How plans renew: invoices, reminders, the grace period and what customers can do themselves.

Area: shop. Module: Subscriptions.

| Field | Type | Help |
| --- | --- | --- |
| Send the renewal invoice this many days early (`leadDays`) | number | The renewal order is created this many days before the plan ends and emailed to the customer, who pays it like any other order. The new term starts when the current one ends. |
| Grace period (days) (`graceDays`) | number | How long a plan stays active after its end date while the renewal is unpaid. Paying inside this time continues the plan with no gap. After it, the plan expires. |
| Reminder emails (`reminderDays`) | text | Days before the end date when an unpaid renewal is reminded, separated by commas. Leave empty to send only the renewal invoice. |
| Renewal price (`renewalPrice`) | segmented | Locked: customers renew at the price they first paid, even if you raise the package price later. Follow: each renewal uses the package price at that time. Tax is always worked out again at renewal. |

| Customers can stop renewing (`customerCanStop`) | switch | Shows a "Stop renewing" button on the customer’s plan page. The plan keeps working until the end of the paid term. |
| Customers can restart an ended plan (`customerCanRestart`) | switch | Shows a "Start again" button after a plan has expired or ended. It creates a new invoice for a fresh term starting on the day it is paid. |
| A full refund of the latest term ends the plan (`refundEndsPlan`) | switch | When the order for the current term is fully refunded, the plan is cancelled at once. Off: the plan only gets a note and you decide. |
| Email me about new and ended plans (`ownerAlerts`) | switch | Sends a short alert when a plan starts, expires or is stopped by the customer. |
